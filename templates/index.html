Step-by-Step Guide • 1. Bulk DNS Manager

Purpose: Add, replace, or delete one DNS record type across up to 1,000 Cloudflare domains in parallel, with optional SSL mode updates.

  1. Step 1 — Cloudflare Token: Choose a saved Cloudflare account above or paste a User API Token with Zone:Read, DNS:Edit, and Zone Settings:Edit.
  2. Step 2 — Domain List (Max 1,000): Paste one domain or subdomain per line. Click Clean & Deduplicate to remove https://, paths, and duplicates.
  3. Step 3 — Action & Record Details: Pick Replace / Create (overwrites matching records), Add If Missing (leaves existing records intact), or Delete Record. Select Record Type, Name (@ = root), and Content.
  4. Step 4 — Proxy, Delay & Dry-Run: Keep Proxy Enabled checked only for A/AAAA/CNAME web records. Check Dry-Run (Preview) to test without writing DNS changes.
  5. Step 5 — Execute & Follow Up: Click Execute Bulk DNS (or Ctrl + Enter). Filter Failed rows if needed, click Retry Failed, and click Export Tab CSV.
Max: 1,000 rows / run

Step-by-Step Guide • 2. CSV Multi-Record Import

Purpose: Apply multiple DNS record types (A, CNAME, MX, TXT) or domain-specific values in one batch (up to 1,000 CSV rows).

  1. Step 1 — Download Sample CSV: Click Download Sample CSV to inspect the exact column headers and sample values.
  2. Step 2 — Populate Rows (Max 1,000): For each row, enter domain, action (replace, add_if_missing, or delete), type, name, and content.
  3. Step 3 — Proxy & MX Priority: Set proxied=true only for A/AAAA/CNAME records, and add numeric priority (such as 10) for MX records.
  4. Step 4 — Upload & Run: Select your .csv file, ensure your Cloudflare token is set above, and click Upload & Run CSV.

Step-by-Step Guide • 3. SSL/TLS & Cache Purge

Purpose: Update SSL/TLS encryption modes, force HTTPS traffic, and purge Cloudflare cached assets for up to 1,000 domains at once.

  1. Step 1 — Paste Domains (Max 1,000): Enter one domain per line and optionally click Clean & Deduplicate.

  4. Step 4 — Apply: Click Apply SSL & Cache and review the live table results.

Step-by-Step Guide • 4. Bulk Domain Redirects

Purpose: Create 301 or 302 forwarding Page Rules across up to 1,000 Cloudflare zones so root or all domain traffic forwards to a subdomain or destination URL.

  1. Step 1 — Paste Root Domains (Max 1,000): Enter one root domain per line (e.g., example.com).
  2. Step 2 — Choose Redirect Mode: Select Root → Subdomain (enter prefix like www or app) or All Traffic → Custom URL (use {domain} if you want each domain inserted into the target URL).
  3. Step 3 — Set Status & Path Options: Pick 301 (permanent) or 302 (temporary), keep Preserve URL Path checked to keep paths, and keep Auto-add Proxied Root A checked if a zone has no root A record yet.
  4. Step 4 — Create Rules: Click Create Bulk Redirects and check each domain's result.

Step-by-Step Guide • 5. Add Zones & Fetch Nameservers

Purpose: Create new Free-tier Cloudflare zones in bulk or pull assigned Cloudflare nameservers (ns1 / ns2) for up to 1,000 domains.

  1. Step 1 — Load Target Account: Ensure your Cloudflare token has Account Settings:Read and Zone:Edit permissions, then click Load Accounts and select the destination account.

Step-by-Step Guide • 7. Dynadot → Cloudflare Migration

Purpose: End-to-end migration of up to 1,000 Dynadot domains into Cloudflare—creates zones, updates Dynadot nameservers (set_ns), imports existing A records, configures SSL/HTTPS, sets auto-renew, and optionally injects custom DNS records.

  1. Step 1 — Enable Dynadot API3 & Whitelist IP: Log into Dynadot (Tools → API), turn API status ON, copy your API3 key, and add your current public IPv4 address to the Dynadot IP whitelist.
  2. Step 2 — Save Dynadot & Select Cloudflare Account: Save your Dynadot account profile above, then click Load Accounts and pick your destination Cloudflare account.
  3. Step 3 — Paste Domains & Configure Settings: Enter up to 1,000 domains. Keep Import Dynadot A Records checked to preserve existing root IPs, set SSL/TLS and Dynadot Auto-Renew, and check Also Add Specified DNS Records to add A, CNAME, MX, or TXT records immediately.
  4. Step 4 — Sync & Verify: Click Sync Dynadot NS → Cloudflare. If any domain fails (e.g., IP whitelist or rate limit), filter Failed and click Retry Failed.

Step-by-Step Guide • 8. AWS S3 Static Hosting

Purpose: Create public S3 static website buckets, configure Cloudflare CNAME records + Flexible SSL, verify live HTTP 200 OK responses, or tear down buckets for up to 1,000 domains.

  1. Step 1 — Save AWS S3 Credentials: Use an IAM user with AmazonS3FullAccess, paste the Access Key ID and Secret Access Key above, and click Save AWS Account.
  2. Step 2 — Select Operation Mode & Region: Choose Deploy Static Website + Update CF DNS to create buckets and point Cloudflare CNAMEs, Verify Live HTTP (200 OK) to check live sites, or Teardown to delete buckets and CNAMEs.
  3. Step 3 — Configure SSL & CNAME Options: Keep Set SSL/TLS to Flexible and Enable Always Use HTTPS checked because S3 website endpoints serve over HTTP.
  4. Step 4 — Execute: Paste up to 1,000 domains and click Execute AWS S3 Action.

Step-by-Step Guide • 9. Google Postmaster Tools DNS

Purpose: Enroll root domains or subdomains in Google Postmaster Tools, add the google-site-verification=... DNS TXT record in Cloudflare, and verify ownership in bulk (up to 1,000 domains).

  2. Step 2 — Monitor Live Token Countdown: The timer badge below Save Google Account displays the exact remaining seconds in real time (The access token will expire in ... seconds). If it approaches 0, generate a fresh token before running a large batch.

  4. Step 4 — Verify & Refresh Postmaster UI: Click Verify Postmaster & Sync DNS. Once finished, refresh postmaster.google.com (Ctrl + F5) to confirm green Verified status.

Step-by-Step Guide • 11. Amazon SES Verification & DNS

Purpose: Enroll domains in Amazon SES across 35 AWS regions, inject 3 Easy DKIM CNAME records (Proxy OFF), merge SPF, configure DMARC, and optionally attach Custom MAIL FROM or SNS bounce/complaint notifications (up to 1,000 domains).

  1. Step 1 — Save AWS SES IAM Credentials: Use an IAM user with AmazonSESFullAccess, select the target SES Region (e.g., us-east-1 or ap-south-2), and save the profile.
  2. Step 2 — Choose Operation Mode: Select Enroll in SES + Add CF DNS + Verify for full provisioning, or Check Existing SES Status Only to audit current DKIM and sending readiness.
  3. Step 3 — Configure DNS & Optional Routing: Keep Smart SPF Merge and Add SES DMARC checked; enable Custom MAIL FROM or enter an SNS Topic ARN / Configuration Set only when needed.
  4. Step 4 — Run Sync: Paste up to 1,000 domains, keep Verify Poll (Sec) at 0 for fast parallel runs, and click Execute Amazon SES Sync.
